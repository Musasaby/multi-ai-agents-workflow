# 計画: 理解確認(Comprehension Check)skill の追加

## 背景・目的

AIエージェント任せの実装で「自分が理解しないままコードが積み上がる」ことを防ぐため、
実装後に AI がユーザーへ質問を出し、回答に応じて解説するフローをワークフローに追加する。

### 制約

1. **実装クオリティを下げない** — 実装・レビューのループ自体には介入しない
2. **コンテキストを汚染しない** — オーケストレーターの会話に余計な読み込み・長い問答を持ち込まない

## 設計方針

### 質問の「生成」と「出題」を分離する

- **生成**: `agent-review-commit` のレビュー合格時点では、diff・受け入れ基準・完了報告が
  すでに親のコンテキストに揃っている。ここで質問を生成すれば追加の読み込みコストはゼロ。
  生成した質問は `.agents/workflow/comprehension/<タスクID>.md` に書き出すだけで、会話には展開しない
- **回答・解説**: ファイルベースの問答とする。対話ツール(AskUserQuestion)には依存しない。
  ユーザーは任意のタイミング(**別セッションでも可**)で質問ファイルに回答を記入し、
  `/agent-comprehension-check [タスクID]` を実行すると AI が判定・解説する

### 質問ファイルのフォーマット

```markdown
# 理解確認: T1-1 <タスクタイトル>

## メタデータ(別セッション解説用)
- コミット: <hash>
- 主な変更ファイル: src/foo.ts, src/bar.ts
- 関連する受け入れ基準: ...

## Q1: <設計判断を問う質問>
(選択式の場合: A/B/C/D の選択肢、もっともらしい誤答肢つき)

**あなたの回答**: <!-- ここに記入 -->

## Q2: ...
```

### 解説フロー(別セッション対応)

`/agent-comprehension-check [タスクID]` は:

1. `.agents/workflow/comprehension/` 配下の**回答記入済み・未解説**のファイルを検出
   (引数でタスクID指定時はそのファイルのみ)
2. メタデータのコミットハッシュ・ファイルパスから**必要最小限のコードだけ**を読み直す
   (別セッションでも文脈を復元できる)
3. 回答を判定し、誤答・曖昧な回答には該当コードを引用した解説を
   同ファイルの「## 解説」セクションに**追記**する(会話には要約のみ)

### 質問観点テンプレート(SKILL.md に明記)

- **設計判断**: なぜこの実装方針か、トレードオフ
- **動作の仕組み**: 変更したコードの処理フロー、エッジケース
- **依存の理解**: 実装で利用した既存モジュール・外部ライブラリ・フレームワーク機能について、
  その大まかな役割と仕組み(例: 「この実装で使っている `useSWR` はどういう仕組みでキャッシュを返すか」)
- **影響範囲**: この変更が他のどこに影響しうるか

### config 拡張

`_templates/workflow/config.json` に追加(デフォルト無効=既存利用先に影響なし):

```json
"comprehension_check": {
  "enabled": false,
  "questions_per_task": 3
}
```

## 実装フェーズ

### Phase 1: 新skill `agent-comprehension-check/SKILL.md`

- 引数: タスクID(省略時は回答記入済み・未解説の全タスク)
- 手順: 質問ファイル検出 → 最小限のコード読込 → 回答判定 → 解説追記 → 会話には要約のみ
- 質問観点テンプレート(設計判断・動作の仕組み・依存の理解・影響範囲)を含める
- どのエージェント(Claude Code / OpenCode 等)でも動作するファイルベース設計

### Phase 2: 既存skillへの統合(最小差分)

- `agent-review-commit`: 合格時手順に「config の `comprehension_check.enabled` が true なら、
  レビューで把握済みの内容から質問を生成し `comprehension/<タスクID>.md` に保存」を追加
- `agent-workflow`: フロー図・サマリー報告に理解確認ステップへの言及を追加
  (サマリー時に未回答の質問ファイル一覧を提示)
- `_templates/workflow/config.json`: `comprehension_check` セクションを追加

### Phase 3: ドキュメント・配布

- `README.md`: 「含まれるもの」表・「ワークフローの流れ」に追記
- `_templates/AGENTS.md`: 理解確認フローへの1行言及
- `.agents/skills/` への手動同期(squash split → read-tree の既知手順)

### Phase 4: 検証

- ダミーの質問ファイルで 回答記入 → 解説追記 のフローが完結することを確認
- 別セッション(コンテキストなし)を想定し、メタデータのみから解説可能かを確認

## リスク

- **MEDIUM**: 質問の質が diff の表面に寄る(「何を変えたか」ばかりで「なぜか」を問わない)
  → 質問観点テンプレートで対策
- **LOW**: 解説時にコード再読込が発生しコンテキストを消費
  → メタデータで読込範囲を最小化する旨を SKILL.md に明記
