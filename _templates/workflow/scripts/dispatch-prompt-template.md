## 実装ルール
- AGENTS.md のルールに従うこと
- 最初に読むのは、タスクの「参照ファイル」欄に挙げたファイル(範囲の指定があればその範囲)と
  「変更対象」のファイルだけにすること。それ以外のファイルは、実装中に必要になった時点で必要な
  部分だけ読む。調査を続けるより先に実装に着手し、テストの結果で確かめること
- 外部コマンド(gh・git 等)の挙動はタスクに書かれた内容を事実として扱い、確かめるために
  プロジェクト外で試さないこと。書かれていない挙動に依存する場合は、その旨を完了報告の備考に書く
- コミットは行わないこと(コミットは親エージェントが行う)。`git commit`・`git config`・
  ブランチ作成などで本物のリポジトリの git 状態(HEAD・ブランチ・参照・設定)を変えると、
  `dispatch-check` が exit 8(tampered)で止める
- プロジェクト外(`/tmp`、ホームディレクトリ等)にファイルを作成・編集しないこと(原則禁止)。
  子エージェントの権限設定によってはプロジェクト外のファイル操作が拒否され、作業が止まる。
  一時ファイル(デバッグ用・テスト出力を保存して後から grep する場合を含む)は、`dispatch-run` が
  `TMPDIR`・`TEMP`・`TMP` を `.agents/workflow/runs/<タスクID>-<試行回数>/tmp/` に設定済みなので
  そこに置くこと(`tmp/` は既に存在するので作成は不要。`tmp/` の中身は削除してよい)。
  `/tmp`・`~/`・`$HOME`・`$env:USERPROFILE`、`bash -c "..."` の文字列内の `/tmp` もプロジェクト外に
  あたるため使わないこと。ツール実行の記録にこれらが現れると `dispatch-check` が
  exit 6(outside-access)で止める(例: `bash -c "bash tests/x.sh > /tmp/out.log"` ではなく
  `bash tests/x.sh > "$TMPDIR/out.log"`)。テストスクリプト自身が `mktemp` 等で一時ディレクトリを
  使うことは構わない(`TMPDIR` 経由で上記の `tmp/` に作られる)
- `.agents/workflow/` 配下の既存のファイル・ディレクトリ(`state.json`・`tasks.md`・`config.json`・
  `scripts/`、`runs/` 配下の `prompt.md`・`output.log`・`done`・`report.md` 等)は読み取りのみとし、
  編集・空にする・削除・移動をしないこと。親エージェントが実行状況の追跡に使う管理ファイルであり、
  実行ディレクトリ自体も削除してはならない
